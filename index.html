The Problem & Vision

Finding a room across floors

An entrance pin gets a visitor to the building. Inside, the useful questions change. Which corridor leads to the room? Where is the elevator? On which floor should the visitor get out?

Who uses the map

A surveyor records entrances, corridors, destinations and floor connections. Visitors can then choose a known entrance, search for a room and request a route that avoids stairs.

Our Solution & User Journey

From entrance to destination

  • Choose a building. Browse saved maps or use location to find nearby mapped entrances. Select the entrance where you are standing.
  • Preview a route. Pick a room, check the floor changes and enable Avoid stairs when needed.
  • Walk with the phone. Android estimates motion from steps and heading. A map-constrained particle filter uses the recorded corridors to refine the position estimate.
  • Maintain a building. Survey mode records points and connections. JSON backups carry the graph between the Android app and this viewer.

Live Demonstration Plan

Try the five-floor demo

Open Innovation Centre and choose Try a sample route. Start at Main Entrance on L0 and take East Elevator to Observation Studio on L3.

  • Start the simulated walk. Watch the elevator instruction show the floor where you get out.
  • Switch to the 2D floor view to inspect room labels, or rotate the 3D stack to see the shaft and corridor connections.
  • For a shorter example, choose Learning Centre and follow the route to Room 104. Both demo graphs are also available in the Android app.

System Integration & Architecture

On the Android device

  • Motion estimation. KinematicPDR estimates steps and stride. WalkingHeading supplies the direction of travel.
  • Position tracking. The particle filter constrains the walking estimate to the mapped floor. Heading and stride error can still accumulate.
  • Navigation. The route graph joins corridors across mapped stairs and elevators. Find exit searches for a reachable mapped exit.

Maps and storage

  • Compose and Room. Android draws the map and stores buildings, points and connections on the device.
  • JSON exchange. An exported map can be inspected in the browser. Browser walk playback animates a route on the graph.
  • Project archive. GitHub Pages hosts this site. The archive uses a Flask API on AWS EC2 and Backblaze B2 object storage.

Project Status & Architectural Roadmap

Available today

  • Walk-based surveying with editable map points and connections.
  • Offline Android navigation with route preview, floor changes and arrival feedback.
  • Two bundled demo buildings, an interactive floor stack and portable map backups.

Next experiments

  • Measure position drift on repeat walks along known corridors.
  • Evaluate Wi-Fi fingerprinting and Bluetooth observations as occasional position corrections.
  • Investigate visual and pressure sensors for heading calibration and floor-change detection.
